# 炳哥输入开发过程

## 1. 项目目标

项目从“五笔＋拼音、支持 Windows 10/11”的需求开始，采用逐阶段沟通、实现和实机验收的方式推进。长期设想还包括输入习惯学习、个性化联想、更多五笔方案以及可选 AI 能力，但原型阶段首先验证 TSF、词典查询、候选窗和安装升级链路。

## 2. 技术路线

- **系统接口**：Windows Text Services Framework（TSF）。
- **实现语言**：原生 C++17、COM 进程内服务器。
- **构建工具**：MSVC、Windows SDK、CMake、Ninja，静态链接 CRT。
- **候选窗**：Win32 窗口和 GDI，支持 DPI、多显示器及屏幕边缘约束。
- **词典**：Rime YAML 转换为 UTF-8 TSV，再作为 `RCDATA` 嵌入 DLL。
- **查询**：按编码排序的只读扁平表，通过二分查找进行精确查询。
- **设置**：`HKCU\Software\TV1TSF` 保存方案、横竖排和全半角标点。
- **安装**：系统 `regsvr32` 注册 COM/TSF，版本化 DLL 支持并行升级。

选择 TSF 而不是模拟键盘，是为了通过系统正式接口处理组合串、编辑会话、候选上屏和应用焦点。项目不依赖网络服务，也不读取或上传输入原文。

## 3. 阶段演进

### TV1：最小 TSF 原型

目标是打通最小闭环：COM 注册、TSF Profile、按键事件、组合串、候选窗和文本上屏。

这一阶段解决了构建环境、TSF 接口签名、类厂和引用计数等基础问题。首次实机只能输入英文，定位到遗漏 `ITfKeystrokeMgr::AdviseKeyEventSink`；补充按键 Sink 注册/注销后，拼音候选可用。

### TV2：完整拼音与五笔86

引入简体全拼和标准五笔86数据，实现方案切换、候选查询和设置持久化。词库转换固定上游提交，保留许可证，并公开可修改 TSV 和转换脚本。

实机发现普通按键处理不能可靠承担方案切换，后改用 TSF `PreserveKey`。候选窗增加当前方案文字，切换后无需输入编码即可看到状态。

### 安装升级：版本化 DLL

早期覆盖安装会遇到 DLL 被记事本等进程占用。为减少重启，安装脚本改为注册 `TV1TSF.vN.dll` 等新文件：

1. 新启动的应用加载新版。
2. 已打开的应用暂时继续使用旧版。
3. 可删除的旧 DLL 自动清理，占用文件保留。
4. 不强制结束用户应用，也不要求每次升级重启 Windows。

同时修复了 PowerShell 严格模式下的变量和错误对象处理问题，卸载脚本从 CLSID 注册值定位当前版本化 DLL。

### TV3：五笔＋全拼混输

五笔方案下同时查询五笔表和拼音表，稳定合并候选：五笔优先、拼音随后、文本去重。五笔表只查询不超过四码的编码，拼音仍支持完整编码，避免改变五笔查词边界。

自动测试覆盖 `a`、`wen`、`wq`、`ggtt`、`nihao`，验证首选顺序、拼音候选存在以及候选不重复。

### TV4：大写英文、标点和快捷键

根据实机反馈进行以下调整：

- F5 是常见应用刷新键，方案切换改为 F8，并同时更新普通键和 PreserveKey。
- 新增 Ctrl+. 切换全角/半角标点，保存用户选择。
- CapsLock 开启时取消组合串并进入英文，关闭时恢复之前的中文状态。
- Shift 单按切换中英文；Shift 与其他键组合时，松开不误切模式。
- 全角支持常用 OEM 和 Shift 数字标点，候选状态显示“·全角”或“·半角”。
- 组合串内未按 Shift 的逗号/句号继续优先翻页。

### v9 / v10：修正“接管后放行无上屏”

实机发现半角标点和 Shift+字母没有输出。两处路径有相同根因：TSF 已接管按键后，仅设置 `eaten=FALSE` 并依赖应用继续接收字符，实际应用没有收到。

修复方式是不再依赖放行，而是在同步读写编辑会话中通过 `ITfInsertAtSelection` 直接上屏：

- v9 增加完整 ASCII 标点映射，全角和半角均直接插入对应字符。
- v10 对 Shift+字母先取消组合串，再直接插入大写 ASCII 字母。

### v11：产品更名

用户可见 TSF Profile 名称改为“炳哥输入”。CLSID、Profile GUID 和配置注册表路径保持不变，以沿用现有设置并避免更名产生另一套技术配置。

## 4. 关键设计记录

### 五笔优先的混输

五笔方案不是简单地只查五笔表，而是先查五笔，再查拼音，并按文本去重。这样 `a` 的首选仍为“工”，同时保留“啊、阿”等拼音候选；`nihao` 即使没有五笔四码匹配，也能返回“你好”。

### 组合串与直接上屏

编码字母进入 TSF 组合串；候选上屏、全半角标点和 Shift 大写则通过编辑会话修改文本。完成或取消组合串时释放相关 COM 对象并隐藏候选窗，避免状态残留。

### 保留键与普通键

Ctrl+Space、F8、Ctrl+. 使用 TSF PreserveKey。字母、数字、翻页、编辑键、Shift 和 CapsLock 通过 `ITfKeyEventSink` 处理。CapsLock 最终放行给 Windows，使系统锁定状态正常变化。

### 隐私边界

当前版本不实现个人学习，因此没有输入历史数据库。诊断日志只写激活、按键准备和模式事件，不记录输入原文。词库查询完全离线。

## 5. 验证方式

自动验证包括：

- Release 构建，编译警告视为错误。
- `DictionaryTests.exe` 词典回归。
- PowerShell 脚本语法检查。
- COM 导出和 DLL 依赖检查。
- 发布 DLL 与打包 DLL 的 SHA-256 一致性检查。

实机验证包括：

- 拼音、五笔和混输候选。
- 选词、翻页、上屏和横竖排。
- F8、Ctrl+.、CapsLock、Shift 及组合串边界。
- 安装、并行升级、卸载和应用重开后的 DLL 加载。

自动测试不能替代 TSF 实机测试。后续如需发布稳定版，还应扩大记事本、浏览器、Office、终端及高 DPI 多显示器场景的兼容测试。

## 6. 后续规划

原始需求中的输入习惯学习、个性化联想和 AI 尚未实现。合理推进顺序是：

1. 完善整句、简拼、模糊音和兼容测试。
2. 设计仅本地保存的学习数据及清除机制。
3. 加入个人词频和排序策略，并提供开关。
4. 实现可解释的个性化联想。
5. 在明确本地处理、网络请求和数据边界后评估 AI 能力。

详细逐版记录见项目根目录的[构建与验证](../构建与验证.md)。
